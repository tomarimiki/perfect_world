## 1. 何を作るのか

### 完成イメージ

黒い画面の中央に太陽があり、水星・金星・地球・火星が楕円軌道を描いて回っています。
それぞれの惑星は色つきの軌跡（トレイル）を残します。

画面の右側にスライダーが並んでいます。

- 「空間の次元」を 3.0 から 3.4 に動かすと、閉じていた楕円がだんだん閉じなくなり、
  軌道が花びらのように広がりはじめる
- 「相対論の強さ」を上げると、水星の楕円がゆっくり回転しはじめる
- 「重力波」を上げると、水星が螺旋を描いて太陽に落ちていく

画面下部には全エネルギーのグラフがあり、法則を壊した瞬間に線が折れ曲がります。

### 作らないもの（最初は）

- 3D表示（内惑星はほぼ同一平面上にあるので、2Dで十分かつ見やすい）
- 外惑星（木星以遠。スケールが10倍以上違い、同時に表示できない）
- リアルな惑星テクスチャ（後回し）

## 2. 技術選定と、その理由

### 結論：素のHTML + JavaScript + Canvas 2D

| 項目 | 選択 | 理由 |
|---|---|---|
| 言語 | JavaScript | ブラウザでそのまま動く。環境構築がほぼ不要 |
| 描画 | Canvas 2D API | ライブラリ不要。5天体なら性能は全く問題ない |
| 物理 | 自作 | **既製の物理エンジンは法則が固定されていて壊せない** |
| ビルド | なし | npm も webpack も使わない。HTMLを開けば動く |
| 3Dライブラリ | 使わない | 内惑星の軌道傾斜角は最大7度。2Dで実用上問題ない |

### なぜ Three.js を使わないのか

3Dは見栄えがしますが、**軌道の変化が奥行きで潰れて分かりにくくなります**。
このアプリの主役は「軌道の形がどう壊れるか」なので、真上から見た2Dが最適です。

3Dにしたくなったら、6章の物理エンジンはそのまま流用できます。描画だけ差し替えれば済みます。

### なぜ物理エンジンを自作するのか

Rapier、Cannon.js、Matter.js などの既製エンジンは、重力が「距離の逆二乗」に固定されています。
**このアプリの目的は、まさにその2という数字を書き換えることです。**
したがって自作以外の選択肢がありません。

安心してください。今回書く物理コードは全部で50行程度です。

## 5. データ設計

### 5-1. 単位系（最重要）

**メートルとキログラムは絶対に使わないでください。**

太陽の質量は 1.989×10³⁰ kg、重力定数は 6.674×10⁻¹¹。
この2つを掛け合わせると、JavaScriptの浮動小数点数の精度が溶けて、計算結果が壊れます。

代わりに以下の単位を使います。

| 量 | 単位 | 意味 |
|---|---|---|
| 距離 | AU（天文単位） | 太陽〜地球の距離 = 1 |
| 時間 | 年 | 地球の公転周期 = 1 |
| 質量 | 太陽質量 | 太陽 = 1 |

この単位系だと、**重力定数が G = 4π² ≈ 39.478** というきれいな値になります。
これはケプラーの第三法則（T² = a³）から自動的に導かれる、美しい帰結です。

光速は c = 63241 AU/年 です。

### 5-2. 惑星データ

初期位置は**近日点**（太陽に最も近い点）に置きます。
そこでの速度はビス・ビバの式から計算でき、全惑星が同じ式で初期化できて楽です。

- 位置：`x = a(1-e)`, `y = 0`
- 速度：`vx = 0`, `vy = √( G/a × (1+e)/(1-e) )`

`data.js`：

```javascript
export const G = 4 * Math.PI * Math.PI;   // 39.478
export const C_LIGHT = 63241.077;          // 光速 [AU/年]

// a: 軌道長半径[AU], e: 離心率, m: 質量[太陽質量]
const ELEMENTS = [
  { name: '水星', a: 0.38710, e: 0.20563, m: 1.6601e-7, color: '#a89078', r: 3 },
  { name: '金星', a: 0.72333, e: 0.00677, m: 2.4478e-6, color: '#e8c07a', r: 5 },
  { name: '地球', a: 1.00000, e: 0.01671, m: 3.0035e-6, color: '#5b9bd5', r: 5 },
  { name: '火星', a: 1.52368, e: 0.09340, m: 3.2271e-7, color: '#c1502e', r: 4 },
];

export function createBodies() {
  const bodies = [{
    name: '太陽', x: 0, y: 0, vx: 0, vy: 0,
    m: 1.0, color: '#ffd75e', r: 12, trail: []
  }];

  for (const p of ELEMENTS) {
    bodies.push({
      name: p.name,
      x: p.a * (1 - p.e),
      y: 0,
      vx: 0,
      vy: Math.sqrt(G / p.a * (1 + p.e) / (1 - p.e)),
      m: p.m,
      color: p.color,
      r: p.r,
      trail: []
    });
  }
  return bodies;
}
```

## 6. 物理エンジンの設計

### 6-1. 全体の考え方

物理エンジンがやることは、毎フレーム以下の2つだけです。

1. すべての天体ペアについて、働く力を計算する
2. その力から速度を更新し、速度から位置を更新する

「法則を壊す」とは、**1番の力の計算式を書き換えること**です。
したがって、力の計算を `computeAccel()` という1つの関数に閉じ込めます。
すべての法則改変はこの関数の中で起こります。

### 6-2. 積分法：なぜ Leapfrog なのか

位置と速度を更新する方法（積分法）には種類があります。

**オイラー法**（最も単純）は、こう書きます。

```javascript
v += a * dt;
x += v * dt;
```

これは動きますが、**エネルギーが勝手に増え続けて、数十周で惑星が飛んでいきます**。
すると「法則を壊したから軌道が乱れた」のか「積分がバグって乱れた」のか区別できなくなり、
このアプリの根幹が崩れます。

**Leapfrog（蛙跳び法）**は、速度を半ステップずらして更新します。

```javascript
v += a * dt / 2;   // 半歩
x += v * dt;       // 一歩
// 新しい位置で加速度を計算し直す
v += a_new * dt / 2;  // 残り半歩
```

たった1行増えるだけで、**エネルギーが長期間保存され、数千年回しても軌道が崩れません**。
さらに時間反転対称なので、dt を負にすると惑星が正確に元の配置に戻ります（これ自体が面白い機能になります）。

### 6-3. 法則パラメータの定義

すべての「壊しどころ」を1つのオブジェクトにまとめます。
これがそのままUIのスライダーになります。

```javascript
export const defaultLaw = {
  G:          4 * Math.PI * Math.PI,  // 重力定数（既定 39.478）
  dimension:  3.0,     // 空間の次元。力の指数 = dimension - 1
  gr:         0.0,     // 相対論補正の増幅率（0 = オフ）
  gw:         0.0,     // 重力波減衰の強さ（0 = オフ）
  lambda:     0.0,     // 宇宙定数（斥力）
  yukawa:     0.0,     // 湯川型の到達距離の逆数（0 = 無限遠まで届く）
  sunMass:    1.0,     // 太陽質量の倍率
  dt:         1 / 2000 // 時間刻み [年]（約4.4時間）
};
```

**dimension について**：D次元空間では重力は距離の (D-1) 乗に反比例します。
3次元なら2乗（現実）、4次元なら3乗。
整数だけでなく **3.0 → 3.4 と連続的に動かせるようにしてください。**
「3.2次元」というあり得ない中間状態を通過するほうが、軌道が徐々に閉じなくなる過程が見えて劇的です。

**dt について**：水星の公転周期は0.24年しかありません。
dt = 1/2000年 なら水星1周あたり約480ステップで、相対論の効果もきれいに出ます。

### 6-4. 力の計算（このアプリの心臓部）

`physics.js`：

```javascript
import { C_LIGHT } from './data.js';

/**
 * 全天体の加速度を計算して配列で返す。
 * 法則の改変はすべてこの関数の中で起きる。
 */
export function computeAccel(bodies, law) {
  const n = bodies.length;
  const acc = bodies.map(() => ({ ax: 0, ay: 0 }));
  const exponent = law.dimension - 1;   // 3次元 → 2乗

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
      if (i === j) continue;

      const A = bodies[i], B = bodies[j];
      const dx = B.x - A.x;
      const dy = B.y - A.y;
      const r  = Math.sqrt(dx * dx + dy * dy) + 1e-9;  // 0除算よけ

      // 相手が太陽なら質量倍率を適用
      const mB = (j === 0) ? B.m * law.sunMass : B.m;

      // --- 基本の重力（次元を変えるとここが変わる） ---
      let a = law.G * mB / Math.pow(r, exponent);

      // --- 湯川型：遠方で力が指数的に消える ---
      if (law.yukawa > 0) {
        a *= Math.exp(-law.yukawa * r);
      }

      // --- 一般相対論補正：近日点移動を生む ---
      if (law.gr > 0) {
        const h = A.x * A.vy - A.y * A.vx;   // 比角運動量
        const corr = 3 * h * h / (C_LIGHT * C_LIGHT * r * r);
        a *= (1 + law.gr * corr);
      }

      acc[i].ax += a * dx / r;
      acc[i].ay += a * dy / r;
    }

    // --- 宇宙定数：距離に比例する斥力（中心から外向き） ---
    if (law.lambda !== 0) {
      acc[i].ax += law.lambda * bodies[i].x;
      acc[i].ay += law.lambda * bodies[i].y;
    }

    // --- 重力波：速度に比例する減衰。螺旋落下を生む ---
    if (law.gw > 0 && i > 0) {
      acc[i].ax -= law.gw * bodies[i].vx;
      acc[i].ay -= law.gw * bodies[i].vy;
    }
  }
  return acc;
}

/**
 * Leapfrog法で1ステップ進める。
 */
export function step(bodies, law) {
  const dt = law.dt;
  let acc = computeAccel(bodies, law);

  // 速度を半歩進める
  for (let i = 0; i < bodies.length; i++) {
    bodies[i].vx += acc[i].ax * dt / 2;
    bodies[i].vy += acc[i].ay * dt / 2;
  }
  // 位置を一歩進める
  for (const b of bodies) {
    b.x += b.vx * dt;
    b.y += b.vy * dt;
  }
  // 新しい位置で加速度を計算し直し、速度の残り半歩
  acc = computeAccel(bodies, law);
  for (let i = 0; i < bodies.length; i++) {
    bodies[i].vx += acc[i].ax * dt / 2;
    bodies[i].vy += acc[i].ay * dt / 2;
  }
}

/**
 * 全エネルギー。法則を壊すとこれが保存しなくなる。
 */
export function totalEnergy(bodies, law) {
  let kinetic = 0, potential = 0;
  for (let i = 0; i < bodies.length; i++) {
    const b = bodies[i];
    kinetic += 0.5 * b.m * (b.vx * b.vx + b.vy * b.vy);
    for (let j = i + 1; j < bodies.length; j++) {
      const dx = bodies[j].x - b.x, dy = bodies[j].y - b.y;
      const r = Math.sqrt(dx * dx + dy * dy) + 1e-9;
      potential -= law.G * b.m * bodies[j].m / r;
    }
  }
  return kinetic + potential;
}
```

### 6-5. 相対論補正について補足

上のコードの `corr` は、増幅なし（`law.gr = 1`）だと水星で約 7×10⁻⁸ という極小の値です。
これは現実そのもので、**100年かけてようやく43秒角しか近日点が動きません**。

なので `law.gr` を 1 から 100000 まで動かせるようにします。

- `gr = 1` … 現実。何も起きないように見える
- `gr = 10000` … 数十秒眺めていると楕円が回りはじめる
- `gr = 100000` … 花びら模様（ロゼッタ軌道）が数秒で描かれる

**「現実は、この効果を10万倍に増幅してようやく目に見える程度の微差だった。
それを19世紀の天文学者は観測で捉え、アインシュタインが説明した」**
という文脈を添えると、体験の質が一段上がります。

## 7. 法則テーブル（UIに出す全項目）

| スライダー名 | 変数 | 範囲 | 既定 | 何が起きるか |
|---|---|---|---|---|
| 空間の次元 | `dimension` | 2.5 〜 4.0 | 3.0 | 3を超えると閉軌道が消滅し、落下か脱出のみになる |
| 重力の強さ | `G` | 10 〜 80 | 39.478 | 上げれば収縮、下げれば散逸 |
| 相対論 | `gr` | 0 〜 100000 | 0 | 近日点移動 → ロゼッタ軌道 |
| 重力波 | `gw` | 0 〜 2 | 0 | 螺旋を描いて太陽へ落下 |
| 宇宙定数 | `lambda` | 0 〜 50 | 0 | 外側の惑星から順に引き剥がされる |
| 重力の到達距離 | `yukawa` | 0 〜 3 | 0 | 遠方で重力が消え、火星から解放される |
| 太陽質量 | `sunMass` | 0.1 〜 3.0 | 1.0 | 減らすと全軌道が一斉に膨張 |
| 時間の流れ | `dt` | -1/500 〜 1/500 | 1/2000 | 負にすると時間が逆行する |

### 各項目の物理的背景（説明文として画面に出すと良い）

**空間の次元** — 超弦理論は空間が9次元あると主張します。もし重力が3次元より高い次元に広がっていたら、
惑星系は成立しません（ベルトラン定理）。我々が3次元にいる理由の一つがこれです。

**相対論** — 水星の近日点は100年に43秒角ずれます。ニュートン力学では説明できず、
一般相対論の最初の実証になりました。

**重力波** — 連星は重力波を出してエネルギーを失い、螺旋を描いて合体します。
LIGOが2015年に観測したのがこの最終段階です。太陽系では効果が小さすぎて事実上ゼロです。

**宇宙定数** — 宇宙の加速膨張の原因。距離に比例する斥力なので、遠方ほど強く効きます。

**湯川型** — 力の到達距離が有限になる形式。余剰次元がコンパクト化されている場合などに現れます。

## 8. 描画の設計

### 8-1. スケールの問題（避けて通れない嘘）

太陽の実直径は 0.0093 AU。火星軌道は 1.52 AU。
**実スケールで描くと、太陽は1ピクセル未満の点になります。**

したがって、ほぼすべての太陽系シミュレータが以下の嘘をついています。

- **距離は実スケール**（軌道の形が正しく見える）
- **天体の半径だけ誇張**（固定ピクセル数で描く）

`data.js` の `r` プロパティがこの誇張半径です。物理計算には一切使いません。

### 8-2. 座標変換

```javascript
const SCALE = 220;    // 1 AU = 220 px（火星が約335pxの位置に来る）

function toScreen(x, y, canvas) {
  return {
    sx: canvas.width  / 2 + x * SCALE,
    sy: canvas.height / 2 - y * SCALE   // 上下反転（数学のy軸は上向き）
  };
}
```

### 8-3. 軌跡（トレイル）

**これが体験の質を決めます。** 点が動くだけでは「壊れた」ことが伝わりません。
軌跡が閉じなくなる、螺旋になる、花びらになる——これが見えて初めて劇的になります。

```javascript
// main.js のループ内、数ステップに1回
b.trail.push({ x: b.x, y: b.y });
if (b.trail.length > 3000) b.trail.shift();
```

`render.js`：

```javascript
export function draw(ctx, bodies, canvas) {
  // 残像を残すため、完全な黒塗りではなく半透明で塗る
  ctx.fillStyle = 'rgba(0, 0, 8, 0.25)';
  ctx.fillRect(0, 0, canvas.width, canvas.height);

  for (const b of bodies) {
    // 軌跡
    ctx.strokeStyle = b.color + '66';
    ctx.lineWidth = 1;
    ctx.beginPath();
    b.trail.forEach((p, i) => {
      const { sx, sy } = toScreen(p.x, p.y, canvas);
      i === 0 ? ctx.moveTo(sx, sy) : ctx.lineTo(sx, sy);
    });
    ctx.stroke();

    // 本体
    const { sx, sy } = toScreen(b.x, b.y, canvas);
    ctx.fillStyle = b.color;
    ctx.beginPath();
    ctx.arc(sx, sy, b.r, 0, Math.PI * 2);
    ctx.fill();
  }
}
```

## 9. UIの設計

### 9-1. 全体をつなぐループ

`main.js`：

```javascript
import { createBodies } from './data.js';
import { step, totalEnergy, defaultLaw } from './physics.js';
import { draw } from './render.js';

const canvas = document.getElementById('canvas');
const ctx = canvas.getContext('2d');

let bodies = createBodies();
let law = { ...defaultLaw };
let simYears = 0;

// 1フレームあたり何ステップ計算するか（描画60fpsに対し物理は細かく回す）
const STEPS_PER_FRAME = 20;

function loop() {
  for (let k = 0; k < STEPS_PER_FRAME; k++) {
    step(bodies, law);
    simYears += law.dt;
  }
  for (const b of bodies) {
    b.trail.push({ x: b.x, y: b.y });
    if (b.trail.length > 3000) b.trail.shift();
  }

  draw(ctx, bodies, canvas);

  document.getElementById('year').textContent = simYears.toFixed(2);
  document.getElementById('energy').textContent = totalEnergy(bodies, law).toExponential(6);

  requestAnimationFrame(loop);
}
loop();

// リセットボタン
document.getElementById('reset').onclick = () => {
  bodies = createBodies();
  simYears = 0;
};
```

**ポイント**：描画は60fpsで十分ですが、物理は細かく回す必要があります。
`STEPS_PER_FRAME = 20` なら 1秒間に 60×20 = 1200ステップ、
dt = 1/2000年 なので**実時間1秒でシミュレーション0.6年**進みます。地球が2秒で1周する計算です。

## 11. 動作確認（必ずやるテスト）

作ったものが正しいかを確かめる方法です。バグと「法則を壊した結果」を区別するために必須です。

### テスト1：周期
すべてのスライダーを既定値にして、地球が1周する時間を測る。
**1.00年ちょうど**でなければ、単位系か初期速度が間違っています。

### テスト2：エネルギー保存
既定値のまま100年回して、全エネルギーの変化率を見る。
Leapfrogが正しく実装されていれば、**変動は0.001%以下**に収まります。
じわじわ増えていくならオイラー法になっています。

### テスト3：時間反転
100年進めたあと `dt` を負にして100年戻す。
**元の配置にほぼ正確に戻れば**、積分法が正しい証拠です。
戻らなければ、Leapfrogの半歩更新のどこかが抜けています。

### テスト4：相対論の値
`gr = 1`（増幅なし）で水星を100年回し、近日点の角度変化を測る。
理論値は **42.98 秒角**（= 2.084×10⁻⁴ ラジアン）です。
これが合えば、相対論の実装は完全に正しいと言えます。

## 12. つまずきポイント集

| 症状 | 原因 | 対処 |
|---|---|---|
| 何も表示されない | `file://` で開いている | Live Server の「Go Live」を使う |
| 惑星が一瞬で消える | 単位系がSI、または初期速度が0 | 5章の検算表と照合 |
| 数十周で軌道が崩れる | オイラー法になっている | Leapfrogの半歩更新を確認 |
| 動きがカクカク | `STEPS_PER_FRAME` が大きすぎる | 20程度に下げる |
| 相対論を上げても何も起きない | 増幅率が小さすぎる | 10000以上にする |
| 次元を4にしたら即座に消える | 正常な物理現象 | 3.1、3.2と徐々に上げる |
| 軌跡が全部繋がって汚い | trailが長すぎる | 上限を1000程度に下げる |
| `Math.pow(r, 2)` が遅い | 指数が整数でないので最適化されない | 5天体なら気にしなくてよい |

### 特に注意：`Math.pow` と負の底

`dimension` を連続値にすると `Math.pow(r, 2.37)` のような計算になります。
`r` は必ず正なので問題ありませんが、**`r` が 0 になると `Infinity` が出て全体が `NaN` に汚染されます**。
コード中の `+ 1e-9` はこれを防ぐためのものです。消さないでください。
